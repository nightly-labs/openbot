Scaling SQLite for local-first apps

By Jonas Weber · June 16, 2026 · 8 min read

When a user's notes live on their own device, the database is not a cache. It is the product. This post describes how we tuned SQLite as our largest users passed 9 GB of notes and attachments.

WAL mode first

Write-ahead logging lets the sync process write while the editor reads. It was the single largest improvement in perceived speed.

PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;

One database, not many

We tried one database per notebook. Opening fifty files at start-up cost more than any query. We went back to one file with good indexes.

Page size and vacuum

A larger page size helped attachment-heavy users. Incremental vacuum keeps the file from growing forever after deletes, without a long pause.
